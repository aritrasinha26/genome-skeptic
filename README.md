# Genome Skeptic

Genome Skeptic is a local-first prototype for agentic bacterial genome assembly and annotation. Its main design rule is simple: a tool finishing successfully is not enough. Every major result is challenged before the workflow advances.

The first release accepts DNA sequencing data only. The intended MVP input is bacterial Illumina FASTQ, especially paired-end reads. The pipeline runs deterministic open bioinformatics tools for measurement and a local language model only for scientific reasoning over the measured results.

The default flow is:

`FASTQ -> input inspection -> fastp QC/cleaning -> SPAdes -> QUAST -> read mapping -> CheckM2 -> Bakta or Prodigal -> annotation validation -> adversarial review -> evidence-backed report`

The agent does not execute arbitrary shell commands proposed by an LLM. It can only choose from registered actions. Hard validation gates always override model suggestions.

## What makes this different

A normal workflow agent asks whether SPAdes completed. Genome Skeptic also asks whether the genome size is plausible, whether contig count and coverage are coherent, whether contamination is suggested, whether the reads actually support the assembly, whether annotation looks biologically plausible, and what evidence could disprove the current interpretation.

Each major conclusion becomes a structured claim with supporting evidence, alternative explanations, disconfirming tests, confidence, and status. The critic agent receives the same evidence independently and is explicitly instructed to try to falsify the proposed conclusion.

## Local model

The reasoning layer is configured for a local Ollama endpoint. The default model name is `qwen3:8b`, but it is configurable. You can use another local model exposed through Ollama without changing the rest of the workflow.

The language model never reads millions of raw reads. It receives compact JSON summaries generated by deterministic tools. This keeps context small and prevents the model from inventing measurements that should have come from sequence analysis.

## Production environment

The canonical benchmark environment is Linux via Docker (`Dockerfile`, `environment.yml`). WSL2/micromamba is supported when Docker is unavailable.

```bash
bash scripts/bootstrap_environment.sh docker   # or: auto | micromamba
bash scripts/check_production_stack.sh
bash scripts/run_realgenome_smoke_test.sh
# Optional large DBs; never automatic:
# bash scripts/download_required_databases.sh bakta-light
# bash scripts/download_required_databases.sh checkm2
```

`genome-skeptic doctor --smoke --out production_stack.json` records tool versions, paths, and whether a smoke test plus required database made the tool operational. An executable on PATH is not treated as operational by itself.

The miniature synthetic benchmark remains a regression test. Production real-genome scores must not be mixed with those numbers.


## Quick start in Cursor

Open this folder in Cursor. Create a Python environment and install the package:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
```

Copy the configuration:

```bash
cp config/example.yaml config/local.yaml
```

Run the preflight check:

```bash
genome-skeptic doctor --config config/local.yaml
```

Then run paired-end reads:

```bash
genome-skeptic run \
  --r1 data/sample_R1.fastq.gz \
  --r2 data/sample_R2.fastq.gz \
  --out runs/sample01 \
  --config config/local.yaml
```

A dry run that only validates inputs and prints the planned stages is available with:

```bash
genome-skeptic run --r1 data/sample_R1.fastq.gz --r2 data/sample_R2.fastq.gz --out runs/test --dry-run
```

## Evidence and stopping behavior

The workflow has two types of checks. Hard gates prevent progression when a result is clearly unusable or a required stage failed. Soft anomalies do not force a stop, but they are sent to the reasoning and critic agents. Examples include unexpectedly high contig count, unusual coverage variation, low mapping rate, poor completeness, or elevated contamination.

Thresholds in `config/example.yaml` are defaults for bacterial isolates, not biological truths. The report keeps them visible and they should be adjusted for the organism and sequencing design.

## Current scope

Version 0.1 is intentionally narrow. It handles DNA sequence analysis for bacterial isolate assembly and annotation. It does not yet attempt metagenome binning, eukaryotic assembly, transcriptomics, proteomics, phenotype prediction, variant calling, phylogenomics, or autonomous literature search.

The next useful milestone is targeted gene reasoning, where a statement such as "gene X is absent" triggers independent attempts to disprove absence using direct sequence search, partial-hit detection, contig-edge inspection, local coverage, and conserved neighborhood evidence.

## Open directly in Cursor

On Windows, unzip the project and double-click `OPEN_IN_CURSOR.bat`. It opens `GenomeSkeptic.code-workspace` in Cursor and loads the whole repository. If the Cursor command-line launcher is installed, this works immediately; the script also checks common Windows Cursor install locations.

The scientific-agent instructions Cursor should preserve are already stored in `.cursor/rules/genome-agent.mdc`.
